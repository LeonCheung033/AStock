# Theme Discovery - 大主题识别引擎

## 一句话定位

> **不是看 "什么已经涨了"，而是发现 "什么产业逻辑正在成立"。自动扫描 + LLM 提炼候选主题，你做最终确认，输出给下游产业链拆解使用。**

## 核心区分：发现 vs 确认



|       | 发现（本 skill 核心） | 确认（辅助验证）     |
| ----- | -------------- | ------------ |
| 问什么   | 什么产业逻辑正在成立？    | 数据是否已经反映？    |
| 看什么   | 事件 + 供需变化      | 涨幅 + 资金 + 热度 |
| 时机    | 比市场早           | 跟市场同步或滞后     |
| alpha | 高（别人还没看到）      | 低（大家都看到了）    |

***

### Step 1a：重大事件梳理（必须输出，不可跳过）

> ⚠️
> **强制要求**
> ：无论何种触发方式，都必须先完成 "重大事件梳理" 并输出完整的事件表格，然后才能进入候选主题评估。禁止跳过此步骤直接输出主题。

#### 信息来源



| 来源              | 用途             | 方式      |
| --------------- | -------------- | ------- |
| 东财全球财经快讯        | 国内产业事件、政策、公司公告 | 自动拉取    |
| Google News RSS | 海外大厂动态、全球供应链变化 | 按关键词定向查 |
| 用户输入            | 你看到的重大事件       | 手动触发    |

#### 高影响力事件识别模式

不是所有新闻都有意义。只关注这几类 "能改变供需关系" 的事件：



| 事件类型        | 示例              | 为什么重要        |
| ----------- | --------------- | ------------ |
| 大厂财报超预期     | 英伟达数据中心收入翻倍     | 直接确认需求爆发     |
| 大额订单 / 产能扩张 | 台积电 CoWoS 扩产 3x | 供给瓶颈 + 需求确认  |
| 政策发布        | 国务院低空经济文件       | 需求侧催化 + 资金引导 |
| 技术路线确定      | 英伟达下一代用 HBM4    | 锁定供应链方向      |
| 供应链紧缺 / 涨价  | HBM 价格上涨 30%    | 供需失衡信号       |
| 产业巨头战略转向    | 苹果自研 AI 芯片      | 新需求维度打开      |

#### 事件梳理输出格式（必须遵循）

拉取新闻后，**第一步必须**按主题方向分组输出事件表格。格式如下：



```
## 一、重大事件梳理

### 🔴/🟢/🟡 [方向标签]：[方向名称]

| 事件 | 要点/供需含义 |
|------|--------------|
| **关键事件1** | 一句话说清要点 |
| **关键事件2** | 一句话说清要点 |
| ... | ... |

**供需逻辑**：[这组事件汇聚后的一段话总结——对谁有利/有害，因果链是什么]

### 🔴/🟢/🟡 [下一个方向]
...（重复上述结构）
```

**颜色标记规则**：



* 🔴 重大变量 / 风险事件（地缘、突发政策、黑天鹅）

* 🟢 正面产业催化（需求爆发、技术突破、涨价信号）

* 🟡 中性 / 待观察（政策框架、宏观数据、尚需验证的信号）

**分组原则**：



* 按产业方向 / 主题归类，不是按时间排列

* 每组 3-10 条事件为宜（太少说明不构成方向，太多需要拆分子方向）

* 每组末尾必须附 "供需逻辑" 总结

* 单条孤立事件归入 "其他值得关注" 表格

**"其他值得关注" 兜底表格**（不构成独立方向但有信息价值的事件）：



```
### 🟡 其他值得关注

| 事件 | 含义 |
|------|------|
| xxx | xxx |
```



***

#### LLM 分析框架（用于事件归类时的内部判断）

对每条有价值的事件，问一个核心问题：**"这个事件对谁有利 / 有害，程度多大？"**

然后按影响类型分类：



| 类型       | 关注什么                    | 示例                                               |
| -------- | ----------------------- | ------------------------------------------------ |
| **供需变化** | 谁的需求在增？谁的供给不足？缺口多大？     | 金山云算力涨价 15-50%、燃气轮机排产到明年                         |
| **政策催化** | 什么方向获得政策支持？力度多大？落地节奏？   | 国务院低空经济文件、工信部行业标准、央行流动性操作                        |
| **技术路线** | 什么技术路径被锁定 / 确认？谁的方案被选中？ | 英伟达选 HBM4、京东方玻璃基载板送样、华为开源鸿蒙                      |
| **资金信号** | 聪明钱在流向哪？市场结构有什么变化？      | 南向净买光纤光缆 9 亿、高盛上调目标价、桥水增持 ETF、芯片 LOF 溢价被监控、资金高低切 |

每类事件汇聚后，判断是否指向同一个大方向。**多条不同类型的事件指向同一方向 = 信号强度高**（如 "算力涨价"+"封装扩产"+"电力订单" 都指向 AI 算力）。



***

### Step 1b：候选大主题评估

> 必须在 "一、重大事件梳理" 输出完毕后，才进入此步骤。

对事件梳理中汇聚出的候选大主题，评估：



1. **规模**：百亿级（小）/ 千亿级（中）/ 万亿级（大）

2. **持续性**：脉冲（一个季度）/ 趋势性（多季度）/ 结构性（多年）

#### 输出格式

对每个候选主题，输出：



1. **主题名称**

2. **触发事件**：按类型列出（供需 / 政策 / 技术 / 资金）

3. **产业逻辑**：一句话说清因果链

4. **规模** + **持续性**

5. **信号强度**：强 / 中 / 弱

6. **建议**：关注 / 观察 / 忽略



***

### Step 1c：时段相关输出（第三部分）

根据不同时段，在 "二、候选大主题评估" 之后输出不同的第三部分：



| 时段 | 第三部分标题       | 内容                         |
| -- | ------------ | -------------------------- |
| 盘前 | **三、今日盯盘重点** | 今天开盘后重点关注哪几条线，具体看什么品种 / 指标 |
| 午盘 | **三、下午关注点**  | 早盘新催化总结，下午盘面需要验证什么         |
| 盘后 | **三、明日预判**   | 盘后公告中的增量信息，对明日开盘的影响判断      |



***

### Step 1d：确认输出

用户确认后的最终输出，供下游 skill 使用：



```
✅ 确认大主题：AI算力扩张
   产业逻辑：全球AI大模型训练/推理需求爆发 → GPU供不应求 → 
            上游算力基础设施全面受益（芯片→封装→存储→服务器→电力）
   当前阶段：初期→加速期过渡（GPU/光模块已涨30%+，封装/MLCC未动）
   规模：万亿级（全球数据中心capex 2025年预计$300B+）
   持续性：结构性（至少3-5年AI投资周期）
   
   → 下一步：进入产业链拆解，找传导缺口
```

## 判断标准：什么不算大主题

避免把每条新闻都当大主题：



| 不是大主题     | 原因             |
| --------- | -------------- |
| 单只个股暴涨    | 可能是游资炒作，不是产业逻辑 |
| 概念炒作无业绩支撑 | "蹭热点" 不等于供需改变  |
| 一次性政策脉冲   | 补贴一年就结束，不够持续   |
| 规模太小的细分   | 百亿以下市场撑不起大主题   |
| 已经过热的老主题  | 全面暴涨后再进 = 接盘   |



***

## 大主题的生命周期管理

大主题不是发现一次就完了，需要持续跟踪：



```
发现 → 确认 → 跟踪阶段变化 → 过热后标记"毕业"
```

每次触发这个 skill 时：



1. 先检查已确认主题的阶段变化（有没有从初期进入加速期？有没有过热？）

2. 再扫描有没有新的候选主题

3. 输出：现有主题状态更新 + 新候选

## 数据实现备注

### 新闻拉取：东财全球财经快讯（翻页版）

akshare 的 `stock_info_global_em()` 只返回最新 200 条（约 6 小时）。直接调底层 API + 用返回的 `sortEnd` 翻页，可覆盖任意时间跨度：



```
import requests

url = "https://np-weblist.eastmoney.com/comm/web/getFastNewsList"
params = {
    "client": "web",
    "biz": "web_724",
    "fastColumn": "102",
    "sortEnd": "",       # 空=最新；填上一页返回的sortEnd=翻页
    "pageSize": "200",
    "req_trace": "1710315450384",
}

all_items = []
for page in range(pages_needed):  # 4页=800条≈24小时
    r = requests.get(url, params=params)
    data = r.json()
    all_items.extend(data["data"]["fastNewsList"])
    params["sortEnd"] = data["data"]["sortEnd"]  # 关键：用返回值翻页
```

每页 200 条，每小时约 30-35 条快讯。按时段拉取：



* 盘前（隔夜 14h）：约 3 页

* 午盘（3.5h）：1 页

* 盘后（3.5h）：1 页

### 预处理：只去重合并，不做内容过滤

**不过滤任何内容**—— 看似噪音的信息可能是信号（央行操作 = 流动性信号，减持 = 个股负面，多条 "小事" 拼起来 = 新方向）。

只做两类去重：



1. **同一事件多条播报合并**：如 SpaceX 上市相关 15 条→合并为 1 条保留关键信息

2. **盘中价格刷新合并**："标普涨 0.3%"" 标普涨 0.5%"→只保留最终状态

去重后交给 LLM 做供需逻辑判断。

### 与下游 skill 的接口

本 skill 的输出是**文字描述**（确认的大主题 + 产业逻辑 + 阶段），下游 skill（产业链拆解）基于这个描述展开工作。不需要结构化数据接口 —— 因为整个流程是对话式的。

## 注意事项



1. **不贪多**：同时跟踪的大主题不超过 3 个，多了精力分散

2. **区分主题和子链**：CoWoS 瓶颈不是新主题，是 AI 算力主题下的子链深化

3. **阶段决定动作**：萌芽 / 初期才有 alpha，加速期只找末端，过热不追

4. **逻辑 > 数据**：产业逻辑成立但数据还没反映 = 最佳时机（萌芽期）；数据已经反映了 = 确认但可能晚了

5. **持续跟踪**：大主题不是一锤子买卖，每周重新评估阶段

6. **快讯涨跌≠收盘**：东财快讯中 "XX 涨 / 跌 N%" 是盘中即时播报，不代表收盘结果（冲高回落很常见）。判断资金方向必须看收盘数据，不能拿盘中播报当结论。快讯的价值在于**事件本身**（谁发了什么公告、什么政策出台），不在于它附带的盘中涨跌描述
