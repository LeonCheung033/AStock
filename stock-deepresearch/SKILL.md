# Deep Research - 产业链深度研究引擎

## 一句话定位

> **一个指令，从事件扫描到选股出池，串联 Skill 1→2→3，输出一篇完整的产业链深度研究报告。**

## 两种触发方式

**方式 A：主动扫描**

> "帮我做一次深度研究"
> "扫描一下现在有什么机会"

从零开始：拉新闻 → 发现主题 → 拆链 → 选股

**方式 B：方向驱动**

> "深度研究一下半导体特气这个方向"
> "AI 算力链帮我从头研究一下"

从指定方向出发：跳过主题发现 → 直接拆链 → 选股



***

## 执行流程



```
触发
  ↓
Phase 1: 主题发现（Skill 1）
  - 拉取新闻（news_fetcher.py）
  - 事件分组 + 供需逻辑提炼
  - 候选主题评估
  - 确认大主题（自动选信号最强的，或用户指定）
  ↓
  输出 → 确认的大主题 + 产业逻辑 + 事件表格
  ↓
Phase 2: 链条推演（Skill 2）
  - 对每条关键事件做追因→拆链→推果
  - 七种分支类型逐一检查
  - 标注传导状态（✅已传导/🟡正在/⭐尚未）
  - 跨事件关联 → 多路径交汇缺口
  ↓
  输出 → 传导网络 + 缺口节点列表（按优先级排序）
  ↓
Phase 3: 选股筛选（Skill 3）
  - 对top 1-3个缺口节点做方向热度判断
  - 三层搜索构建股池（chain_search.py）
  - 纯正度验证 + 可交易性筛选
  - 排除过滤（过热/催化衰竭/证伪/减持）
  ↓
  输出 → 精选候选池（3-5只）+ 角色 + 状态
  ↓
合成：整合为一篇完整报告
```

## 执行规范

### Phase 1 执行要点



1. **必须先拉新闻**：运行 `python3 /Users/bytedance/Documents/stock/theme-discovery/scripts/news_fetcher.py --hours 3`（定时模式拉过去 3 小时；手动可用 `--session full` 拉全天）

2. **必须输出事件表格**：按方向分组，每组附供需逻辑

3. **方式 B 可跳过**：如果用户直接给了方向，跳过新闻拉取，直接进入候选评估

4. **自动确认**：如果只有 1 个强信号主题（⭐⭐⭐），自动确认不等用户；多个则列出让用户选

### Phase 2 执行要点



1. **每条事件（或同类事件）各自催化一条独立传导链**：不同方向的事件产出不同的链，相似事件可合并催化同一条链

2. **七种分支必须逐一检查**：直接 / 替代 / 配套 / 瓶颈 / 横向 / 成本 / 跨链交叉

3. **网状不是线性**：每个节点至少考虑 3 个分支方向

4. **用 chain\_search.py 辅助验证**：推出缺口后用脚本验证公司

5. **多条链独立输出**：每条链各自完整呈现（追因→传导→缺口），不要求必须有交汇点；如果恰好有交汇则额外标注

### Phase 3 执行要点



1. **每条链的缺口节点独立做选股**：不是只选 top 1-3 个缺口，而是每条传导链各自筛选

2. **全线过热直接 pass**：Step 1 判断过热就跳过该节点，看下一个缺口

3. **三层搜索**：概念 + 主营 + 产业链，用 chain\_search.py

4. **纯正度 < 30% 排除**：不浪费篇幅

5. **排除要有数据**：每个排除标明来源

6. **没动的票不排除**：缺乏催化数据≠排除理由

7. **每条链输出 3-5 只精选**：不硬凑，少于 2 只就说 "无合适标的"

## 注意事项

1. **数据先于推理**：每个Phase都要先跑脚本拿数据，再做LLM分析
2. **不跳步**：即使用户说"直接选股"，也要先走Phase 2确认传导逻辑
3. **方式B允许跳Phase 1**：但必须走Phase 2+3
4. **报告要完整**：即使某Phase结果简单，也要在报告中体现
5. **交易限制**：只推荐沪深主板（600/601/603/605/000/001/002/003）
6. **LLM代码不可信**：所有股票代码必须来自pywencai/chain_search.py返回
7. **不硬凑结论**：如果没找到好的缺口/标的，报告结论可以是"当前无明确机会，建议观察"
