# Chain Mapping - 产业链传导推理引擎

## 一句话定位

> **从每一条有价值的事件出发，沿着供需关系向上追因、向下推果，画出网状传导路径，标注每个环节 "传导到了没有"—— 找出逻辑成立但市场尚未定价的缺口。**

## 核心思维模型



```
一组新闻/事件（来自Skill 1或直接输入）
    ↓
每条事件独立推演（不只是候选主题，每条有价值的事件都推）
    ↓
追因：为什么发生？根源是什么？
    ↓
拆链：沿着供需关系，影响会怎么传导？（网状，非线性）
    ↓
推果：谁受益？传导到哪了？哪里还没传到？
    ↓
关联：多条事件是否指向同一根因？（信号放大）
    ↓
输出：网状传导路径 + 每环节状态 + 缺口标注 + 跨事件关联图
```

**与 Skill 1 的关系**：Skill 1 识别事件 / 主题 → Skill 2 对**每条有价值的事件**做传导推理（不只是候选主题）。一条新闻就是一个推演入口。



***

## 关键原则：每条事件都推演

> ⚠️ 
>
> **不要只分析 "候选主题"，要对每条有产业含义的事件做传导推演。**

Skill 1 可能输出 5 个候选主题，但原始新闻中还有很多单条事件也值得推演：



* "尼吉康涨价" 单独就能推出一整棵传导树

* "金山云算力涨价" 可以推出算力→电力→配套→冷却链

* "中石化签储能大单" 可以推出储能→电池→材料→设备

**判断标准**：只要事件涉及 "供需变化 / 涨价 / 扩产 / 紧缺 / 政策催化" 中的任何一个，就值得推演。



***

## 工作流程

### 输入

来自 Skill 1 的一组事件（可以是完整的主题分析结果，也可以是单条新闻）。

### Step 1：追因（向上溯源）

核心问题：**"这件事为什么发生？根本原因是什么？"**

从事件出发往上追：



```
尼吉康全线涨价
  ← 为什么？铝电容供不应求
    ← 为什么？需求激增
      ← 为什么？AI服务器单机电容用量是传统5-8x + MLCC涨价逼大容量场景转向铝电容
        ← 根源：AI算力需求爆发 + MLCC产能结构性短缺
```

追因的目的：



1. 找到**根本驱动力**（是一次性脉冲还是结构性趋势？）

2. 判断**持续性**（根源还在加强？还是已见顶？）

3. 发现**关联链条**（同一个根源可能同时驱动多条传导路径）

### Step 2：拆链（网状传导路径推演）

核心问题：**"这个事件 / 根因沿着供需关系会怎么传导？影响链条上的谁？"**

> ⚠️ 
>
> **传导路径是树 / 网状结构，不是线性的。**
>
>  每个节点都可能分叉出多条路径。

从根因出发，画出完整的网状传导路径：



```
根因：AI算力需求爆发
  │
  ├─ 直接传导：GPU/HBM需求 → 封装(CoWoS) → ABF载板 → 电子玻璃
  │
  ├─ 配套传导：AI服务器 → 电容(MLCC+铝电容) → 电极箔/化成箔
  │                      → 电源(服务器电源) → 磁性材料
  │                      → PCB(高层板) → 电子布/铜箔
  │                      → 散热(液冷) → 冷却液/泵阀
  │
  ├─ 替代传导：MLCC涨价 → 铝电容替代需求外溢
  │            HBM缺货 → 高带宽替代方案(CXL)
  │
  ├─ 瓶颈放大：CoWoS产能不足 → ABF载板需求×3 → 载板设备
  │
  └─ 基础设施：算力扩张 → 电力需求 → 变压器/电缆 → 硅钢片/铜
                                    → 数据中心建设 → 制冷/UPS
```

#### 七种分支类型（必须全部考虑）



| 分支类型     | 含义                     | 示例                        |
| -------- | ---------------------- | ------------------------- |
| **直接传导** | 供需链上下游直接受益             | GPU 放量→CoWoS 封装需求增        |
| **替代效应** | A 涨价 / 缺货→B 作为替代品受益    | MLCC 涨→铝电容替代需求            |
| **配套联动** | 主产品放量→配套辅材 / 设备跟着吃肉    | AI 服务器→电容 / PCB / 散热全受益   |
| **瓶颈放大** | 某环节卡脖子→其上游材料 / 设备需求被放大 | CoWoS 不够→ABF 载板需求 ×N      |
| **横向关联** | 同一产能 / 原料被共用→挤占效应      | 氟化工景气→电子级 HF/NF3 产能被挤     |
| **成本传导** | 上游涨价→中游被动提价→下游选择替代     | 铜涨→电缆涨→铝缆替代               |
| **跨链交叉** | 同批其他事件也指向此环节→因果闭环互验    | 存储涨价 + 设备订单 + 17%→半导体景气确认 |

#### 横向联想（关键改进）

> **同一逻辑模式在不同领域的迁移**

当发现一个传导模式（如 "涨价→替代"）时，主动联想其他领域是否有类似模式：



* 铝电容涨→高分子电容替代（电容领域）

* 铜涨→铝替代（金属领域）

* HBM 缺货→CXL 替代方案（存储领域）

* 光模块铜缆→硅光方案（通信领域）

横向联想不是乱猜，必须满足：



1. 替代品技术上可行

2. 价差 / 性能差已接近切换临界点

3. 有下游客户开始验证 / 导入的信号

### Step 3：推果（传导状态判断）

核心问题：**"传导到哪了？哪里还没到？"**

对每个环节标注传导状态：



| 状态          | 含义          | 投资含义            |
| ----------- | ----------- | --------------- |
| **已传导** ✅   | 股价已反映，市场已定价 | 确认方向对，但追入风险大    |
| **正在传导** 🟡 | 开始反映但未充分    | 顺势参与窗口          |
| **尚未传导** ⭐  | 逻辑成立但股价未动   | **传导缺口 = 核心机会** |
| **传导存疑** ❓  | 逻辑链较远或有不确定性 | 需要更多验证          |

判断依据（可选用 pywencai 验证）：



* 近 5 日涨幅 > 15% → 大概率已传导

* 近 5 日涨幅 5-15% → 正在传导

* 近 5 日涨幅 < 5% → 尚未传导

* 逻辑链超过 3 步 → 传导存疑

### Step 4：跨事件关联（信号放大）

核心问题：**"多条事件是否指向同一个根因或同一条链？"**



```
事件A: 尼吉康铝电容涨价
事件B: 电子布第五轮涨价
事件C: 深南电路募资48.8亿做AI算力PCB
事件D: 金山云算力涨价15-50%
     ↓
共同根因: AI算力需求爆发
     ↓
信号强度: ⭐⭐⭐⭐ (4条独立事件互相印证)
```

**多事件指向同一根因 = 信号极强**。这不是巧合，是产业链上多个节点同时在反映同一个底层变化。

关联分析输出：



* 哪些事件共享根因？

* 哪些传导路径在不同事件的推演中重叠？（重叠 = 确定性更高）

* 有没有某个环节被多条路径指向但尚未反映？（多路径交汇的缺口 = 最高优先级）

## 推理质量要求

### 好的传导推理



1. **因果链清晰**：每一步都有明确的 "因为 A→所以 B"

2. **网状思维**：不是线性推理，每个节点都考虑多条分支

3. **替代效应敏感**：A 涨价→B 作为替代品受益（最容易被忽略）

4. **横向联想丰富**：同一逻辑模式迁移到其他领域（但必须合理）

5. **标注不确定性**：不是每条传导都 100% 成立，用状态标签区分

6. **给出失效条件**：什么情况下这个推理不成立

7. **跨事件关联**：多条事件指向同一根因时一定要标注信号放大

### 七种分支类型（每次推演必须逐一检查）



| 类型   | 核心问题                        | 容易遗漏的场景               |
| ---- | --------------------------- | --------------------- |
| 直接传导 | 上下游谁直接受益？                   | 很少遗漏                  |
| 替代效应 | A 涨价 / 缺货，谁是替代品？            | **最常遗漏**              |
| 配套联动 | 主产品放量，配套辅材 / 设备 / 耗材有哪些？    | 散热 / 检测 / 耗材容易忘       |
| 瓶颈放大 | 哪个环节是瓶颈？其上游设备 / 材料需求会被放大几倍？ | 设备类弹性常被低估             |
| 横向关联 | 同一产能 / 原料被哪些产品共用？挤占 / 共振？   | **第二容易遗漏**            |
| 成本传导 | 上游涨价→中游提价→下游找替代？            | 二阶效应（替代的替代）           |
| 跨链交叉 | 同批其他事件是否也指向这个环节？因果闭环？       | **在路径内标注**，不要只在最后统一关联 |

### 常见传导模式



| 模式         | 示例                   | 关注什么           |
| ---------- | -------------------- | -------------- |
| **涨价传导**   | MLCC 涨→铝电容跟涨         | 替代关系、涨价幅度 / 节奏 |
| **瓶颈放大**   | CoWoS 不够→ABF 载板需求暴增  | 瓶颈产能利用率、扩产周期   |
| **国产替代**   | 美国限制→国产设备份额提升        | 技术成熟度、客户验证进度   |
| **需求乘数**   | AI 服务器→电容用量 5-8x     | 渗透率、ASP、用量增幅   |
| **配套联动**   | 主设备放量→辅材 / 检测 / 耗材跟涨 | 主设备出货确认、配套比例   |
| **产能挤占**   | 氟化工景气→电子气体产能被挤       | 共用产能比例、切换成本    |
| **成本驱动替代** | 铜涨→铝缆替代              | 价差临界点、技术可行性    |

### 避免的错误



1. **逻辑链过长**（>4 步传导，确定性很低）

2. **线性思维**（只有一条线，没有分支 ← 最大问题）

3. **混淆 "有关系" 和 "受益"**（比亚迪用 MLCC≠比亚迪是 MLCC 受益标的）

4. **忽略供给侧**（需求增≠一定涨价，要看供给能否跟上）

5. **把已充分反映的当机会**（+35% 了还说 "尚未传导"）

6. **LLM 代码不可信**：LLM 推理出的股票代码可能错误，只信任 pywencai 返回的代码

7. **横向联想过度**：联想必须有逻辑支撑，不能因为都是 "化工" 就关联

8. **忽略跨事件关联**：如果多条事件指向同一方向，一定要合并分析

### 推荐频率：每 3 小时一次

| -- | ------- | ------------------- | ---------------- |

**为什么 3 小时**：



* 每次积累足够事件做跨事件关联（3 小时约 50-100 条快讯，去噪后 10-20 条有价值事件）

* 留出足够时间做深度网状推演，而不是浅层逐条反应

**例外：重大突发可随时触发**（如大厂财报、重大政策、突发黑天鹅）

* **最低**：Skill 1 的事件梳理表格（分组后的事件）

* **最佳**：Skill 1 完整输出（事件表格 + 候选主题评估 + 原始新闻中的关键单条）

## 注意事项



1. **每条事件都推**：不要只推 "大主题"，任何涉及供需变化的事件都值得一推

2. **网状思维**：每个节点至少考虑 3 种分支类型，不要只画一条线

3. **横向联想要克制**：有逻辑支撑才联想，不能为了多而多

4. **速度 > 完美**：先出框架（主要路径 + 最明显的缺口），再补细节

5. **标注确定性**：不是每步传导都确定，远端标❓

6. **传导有时差**：从龙头到末端通常有 1-5 个交易日的时差，这就是机会窗口

7. **跨事件关联是精华**：单条推演是基础，多条关联才能发现 "确定性最高的缺口"

8. **跨链交叉在路径内标注**：推演事件 A 时如果发现与同批事件 B 有交叉，立刻在 A 的路径内标注`[跨链交叉]`，不要等到最后统一关联才提。这样每条路径自身就是完整的、有上下文的

9. **不可操作的事件果断 pass**：如果推完发现 A 股无可交易标的或逻辑太远，直接说 "pass" 不要硬凑

10. **pywencai 辅助**：推理为主，数据验证为辅。用相关系数 > 60% 过滤核心公司

11. **多路径交汇 = 最高优先级**：被≥2 条独立传导路径指向的缺口环节，确定性远高于单路径
